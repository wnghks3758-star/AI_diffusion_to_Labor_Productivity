# 1. 결론

**현재 코드의 ATET 점추정 핵심은 저자 R 함수와 같은 두 개의 정규화 잔차평균 차이다.**
모형 예측값과 트리밍을 같게 고정하면 실제 R 실행과 Python 계산이 수치 오차 범위에서 일치했다.
따라서 점추정식 전체를 잘못 구현한 상황은 아니다.

그러나 모든 차이를 그대로 정당화할 수는 없다. 커널의 척도, 한쪽만 검사하는 트리밍,
GPS 정규분포 가정과 밀도 하한, 교차적합 안팎의 튜닝·분산 학습, 공변량의 인과적 역할을
구분해야 한다. 특히 **지금 결과를 저자 패키지의 그대로인 재현이나 논문의 모든 이론적 보장이
그대로 적용되는 추정치라고 설명해서는 안 된다.**

이번 작업은 ATET 단계까지의 비교·검증과 GPS 후보 추가이다. 새로운 효과 패턴 탐색은 수행하지 않았다.

| 판단 | 내용 |
|---|---|
| 일치 | 잔차를 이용한 정규화 ATET 점추정 구조 |
| 정당화 가능 | 산업 단위 학습·표본 분할·유효 표본 수를 사용하는 방향, 보수적인 RF 후보 추가 |
| 설정을 명시해야 함 | 커널 척도, bandwidth, 트리밍, 반복별 예측 중앙값, 분산·추론 방식 |
| 추가 정당화 필요 | GPS와 Mu의 공변량 집합 차이, 기업 가중 목표와 산업 단위 GPS의 관계, 고정 밀도 하한 |
| 개선 필요 | 표본 밖 튜닝·GPS 분산 표적의 간접 누출 가능성, 처치 이후 공변량·처치 이력 해석 |

# 2. 비교한 자료와 버전

첨부된 Haddad 등 논문은 최초 공개 연도는 2024년이지만, 파일 표지는
**arXiv:2410.21105v2, 2026년 1월 15일**이다. 패널 자료의 식 (19), 추정 알고리즘,
식 (27)·(28)의 분산 설명을 기준으로 읽었다. 이후 단계의 변환·합산은 비교 대상에서 제외했다.

논문의 시뮬레이션 절은 패널 자료에 `causalweight::didcontDMLpanel()`을 사용한다고 명시한다.
이 패키지는 Haddad 개인의 전용 패키지라기보다 Bodory·Huber 등의 인과추론 패키지이다.

- 현재 비교 버전: **causalweight 1.1.6**, 2026-09-25, 커밋 `84b6412`.
- 역사적 비교 버전: **causalweight 1.1.1**, 2024-07-23, 커밋 `ff0abf5`.
- Python 변경 전 기준: `feature/compact-dml-runner`, 커밋 `c504c24`.
- 커널 정의: `np`의 C 소스. 2022년 버전에서도 같은 Epanechnikov 척도를 확인했다.

R의 문서 설명과 실행 코드가 다르면 실행 코드를 우선 확인했다. 예를 들어 문서는
SuperLearner를 언급하지만 최신 `functions.R`는 같은 인터페이스를 자체 구현한다.

# 3. ATET 핵심 식은 같은가

관심 모수는 특정 두 처치 강도에 대한

$$\tau(d,d')=E[Y_t(d)-Y_t(d')\mid D=d]$$

이다. 패널의 결과 차분과 비교 강도에서의 결과 예측을 이용해

$$r_i=\Delta Y_i-\widehat m(d',X_i)$$

를 정의한다. 정규화 전 가중치를

$$a_i=K_h(D_i-d),\qquad
b_i=K_h(D_i-d')\frac{\widehat p(d\mid X_i)}{\widehat p(d'\mid X_i)}$$

로 쓰면, 같은 제외 집합을 적용한 뒤 두 구현의 점추정은 모두

$$\widehat\tau=
\frac{\sum_i a_i r_i}{\sum_i a_i}
-\frac{\sum_i b_i r_i}{\sum_i b_i}$$

이다. 현재 Python에서 밀도비를 한 번 더 정규화하는 연산은 두 번째 분모에서 상쇄된다.
R에서 커널을 먼저 정규화하는 상수도 마지막 정규화에서 상쇄된다.
이 부분은 차이가 나는 원인이 아니며, 식 전체를 바꿀 이유도 없다.

코드에서는 이 계산을 `labor_did/score.py`의 `normalized_atet_score()`로 분리했다.
`labor_did/atet.py`의 `estimate_atet_point()`는 한 처치쌍만 계산한다.
이 함수는 계산 가능한 원시 ATET와 별도로 `supported`를 반환한다. ESS 기준을 만족하는지는
그 값을 확인해야 한다.

모형 예측을 고정해 **점수 계산만** 비교했으며, 패키지의 전체 학습 과정을 다시 실행한 것은 아니다.

# 4. 실제로 다른 부분과 정당성

## 4.1 커널: 이름이 같아도 bandwidth의 단위가 다르다

기존 Python은

$$K_{unit}(u)=\tfrac34(1-u^2)\,1\{|u|\le1\}$$

을 사용한다. R의 `np`는

$$K_{np}(u)=\frac{3}{4\sqrt5}(1-u^2/5)\,1\{|u|<\sqrt5\}$$

를 사용한다. 따라서 같은 숫자 $h$를 넣으면 R의 지지구간 반폭은 $\sqrt5h$이다.
같은 가중치를 얻으려면 **Python 반폭을 R bandwidth의 $\sqrt5$배로 변환**해야 한다.

둘 다 적절한 2차 커널이므로 Python 커널 자체가 잘못된 것은 아니다.
다만 같은 bandwidth라고 설명하거나 두 결과를 바로 비교하면 잘못이다.
새 `kernel_convention="np"`는 이 척도 변환을 적용한다.
기존 기본값은 `"unit"`으로 유지했다. 연도별 진단에는 규칙의 bandwidth와 실제 반폭을 모두 기록한다.

실제 2023년 자료에서 GPS와 Mu를 고정하고 미리 정한 처치쌍 하나를 비교하면 다음과 같다.

| 항목 | 기존 unit 커널 | 같은 숫자의 np 커널 |
|---|---:|---:|
| 비교쌍 $(d,d')$ | $(3.226067,3.126067)$ | 동일 |
| 규칙의 bandwidth | 0.147471 | 0.147471 |
| 실제 반폭 | 0.147471 | 0.329755 |
| ATET | -0.047439 | -0.035073 |

이 차이는 학습 모형을 바꿔서 생긴 차이가 아니라 평활 범위를 바꾼 결과이다.
이는 민감도 확인이며, 별도의 유의성·목표 패턴 탐색 결과가 아니다.

## 4.2 트리밍: R은 양쪽을 검사한다

R은 제외 전 정규화 가중치가 처리군 또는 비교군 어느 쪽에서든 `trim`을 넘으면
그 관측치를 양쪽에서 제거한 후 다시 정규화한다.
기존 Python은 비교군 가중치만 검사했다.

이는 **실제 구현 차이**이다. 다른 overlap 규칙으로 정의할 수는 있지만,
저자와 동일한 트리밍이라고 할 수 없다. 처리군의 큰 가중치를 놓칠 수 있으므로
새 탐색의 민감도 설정에는 `trim_mode="both"`를 권한다.

다만 이 차이가 기존 1772를 실제로 바꿨는지도 확인했다.
기존 전체·SME·Large 평균 계산에 사용된 **2,605개 끝점**에서 가중치와 점수 구현이
변경 전과 정확히 같음을 확인했고, 양쪽 트리밍으로 바꾸어도 제외 마스크가 바뀐 끝점은 0개였다.
따라서 이 표본과 확인한 끝점에서는 해당 차이가 1772 결과를 설명하는 원인이 아니었다.
다른 설정이나 멀리 떨어진 두 처치쌍에도 같다고 일반화할 수는 없다.

## 4.3 GPS: 정규분포·분산 모형·밀도 하한

R의 기본 `psmethod=1`은 처치의 조건부 평균을 학습한 뒤, 검증 Fold의 잔차제곱 평균으로
Fold별 공통 분산을 사용한다. 현재 Python은 산업별 이분산 분산모형과 smearing 보정을 사용한다.
이분산을 허용하는 것은 가능한 확장이지만 실제 밀도 적합성과 nuisance 수렴 조건이 필요하다.

R의 `dnorm` 호출에 표준편차로 나누는 항이 생략되어 있어도, 같은 Fold에서 두 밀도의 비를
취할 때 그 공통 항이 상쇄된다. 이 생략만을 점추정 오류라고 판단하면 안 된다.

기존 Python의 `density_floor=0.005`는 R 기본 함수에는 없는 장치이다.
수치 폭주를 줄이지만 하한이 실제로 작동하면 밀도비를 바꾼다.
고정 하한이 무시 가능하거나 활성화되지 않는 조건을 확인하지 않은 채 원래의 이중강건성·추론 정리를
그대로 적용할 수는 없다. 관측 처치에서의 하한 작동 비율도 새 GPS 진단에 기록했다.
이는 반사실적 모든 처치점에서의 작동 비율과는 다르다.

Random Forest를 넣어도 이번 구현은 **평균·분산 회귀를 RF로 바꾼 조건부 정규밀도**이다.
분포 가정을 없애는 비모수 조건부 밀도 추정으로 바뀌는 것은 아니다.
R의 `psmethod=2`는 커널 가중치를 직접 회귀하는 다른 선택지이며 이번에는 추가하지 않았다.

## 4.4 교차적합과 튜닝

R 함수는 각 외부 Fold의 학습 자료에서 nuisance 학습 함수를 호출한다.
기존 Python의 Mu 기본값은 전체 표본 CV에서 한 번 고른 파라미터를 외부 Fold에 공통 사용한다.
GPS alpha도 전체 산업의 첫 반복 CV에서 선택한다. 이 선택에는 외부 검증 자료가 관여한다.

또한 기존 GPS 분산 표적은 전체 OOF 중앙값 잔차에서 만든다.
분산 학습 Fold의 학습 관측치에 대한 OOF 평균 예측이 다른 Fold에서 계산되는 과정에서
해당 분산 Fold의 검증 처치가 간접적으로 사용될 수 있다.
따라서 전 단계가 엄격한 외부 표본 분할을 지킨다고 설명할 수 없다.

새 `gps_fit_scope="nested"`는 외부 학습 자료 안에서 평균모형을 학습하고,
그 학습 자료 내부의 OOF 잔차로만 분산 표적을 만든다. RF는 항상 이 방식을 사용한다.
검증 처치를 1,000만큼 바꾸어도 해당 Fold의 평균·분산 예측이 전혀 변하지 않는 테스트를 추가했다.

이것은 **GPS 단계의 개선**이다. Mu까지 엄격하게 하려면 `tuning_scope="nested"` 또는
자료 밖에서 미리 고정한 파라미터가 필요하다. 기존 1772에서 고른 파라미터는 같은 자료에 기반하므로
속도를 위한 고정 예제로는 유용해도 독립적인 사전 명세가 되는 것은 아니다.
GPS와 Mu의 외부 Fold를 완전히 공유하는 전체 DML 프로토콜도 추가 검토할 사항이다.
이번 GPS 개선만으로 전체 파이프라인의 정리 적용이 자동으로 확보되지는 않는다.

R 기본 GPS도 검증 Fold의 처치 잔차를 이용해 공통 분산을 구한다는 점에서
모든 nuisance가 외부 학습 표본에서만 만들어지는 이상적인 구현은 아니다.

## 4.5 산업 단위 학습과 bandwidth

R 기본 bandwidth는 기업행을 넣으면 기업행의 표준편차와 행 수를 사용한다.
현재 Python은 서로 다른 처치 할당이 있는 산업 수 151개와 산업별 분포를 사용한다.
산업 안에서 처치가 같고 오차가 상관될 수 있는 자료에서 독립 정보량을 기업 2,028개로
과장하지 않으려는 방향은 타당하다. 다만 이 군집 자료 적용에는 추가적인 군집 표본 가정이 필요하다.

현재의 robust sigma, 배율 0.45와 R의 표준편차, 기본 배율 0.7도 다르다.
`std`와 `sigma`는 모두 분산 자체가 아닌 처치의 **척도**이다.
R은 기본 `sd`의 표본 표준편차, 현재 코드는 산업 처치의 `ddof=0`을 사용한다.
이는 선택 가능한 평활 규칙의 차이이지 그 자체로 식의 오류는 아니다.

한편 현재 ATET의 최종 목표는 기업 분포인데 GPS는 산업을 동일 가중해 학습한다.
산업별 기업 수가 처치와 조건부로 관련되면 기업 분포의 밀도와 산업 분포의 밀도가 달라질 수 있다.
산업별 처치 할당 메커니즘을 사용하는 계층적 식별 가정, 목표 모집단, 기업 수 가중의 역할을
명시해야 한다. 단순히 산업 단위로 학습했다는 사실만으로 이 정당화가 끝나지는 않는다.

## 4.6 공변량과 고정 처치의 인과적 해석

R 함수는 하나의 `controls` 집합을 받는다.
현재 GPS는 산업 공변량 12개와 산업 더미 20개를, Mu는 기업 변수·규모 더미·산업 변수·처치를 포함한다.
GPS가 더 적은 변수만 조건화하는 것이 충분한지 별도 가정이 필요하다.
추가 기업 변수들이 산업 변수 조건부로 처치 배정을 더 설명하지 않거나, 관련 다른 조건이 있어야 한다.
Mu가 올바르게 추정되면 보호될 수 있어도, 두 모형에 아무 변수나 다르게 넣어도 논문의
그대로인 이중강건성이 유지된다는 주장은 할 수 없다.

`covariate_time="current"`에서 쓰는 임금·자산·R&D 등이 처치의 영향을 받는다면
처치 이후 매개변수 또는 충돌변수를 통제하는 문제가 생길 수 있다.
이는 예측 성능으로 해결되지 않는다. 기본 해석에는 처치 이전 공변량을 사용하거나
처치에 의해 영향받지 않는 변수라는 근거가 필요하다.

논문은 처치 이력을 조건화한 시간변화 처치 모형을 다룬다.
현재 자료의 `office_ratio`는 산업별로 연도에 걸쳐 고정되어 있다.
이 값을 과거 처치로도 그대로 넣으면 현재 강도가 과거 강도에 의해 결정되어 overlap이 사라질 수 있다.
따라서 저자의 처치 이력 변수를 기계적으로 추가하면 안 된다.
정책·충격 발생 전에는 실제 처치가 없고 그 뒤 노출 강도가 달라진다는 설계라면,
이를 명시한 고정 노출의 DiD와 해당 기준연도 대비 효과로 식별 가정을 다시 써야 한다.
2022년 대비 후속 연도 차분을 각 연도의 순수한 순간 효과라고 자동 해석할 수도 없다.

## 4.7 표준오차도 같은가

R은 점수에서 처리군 밀도 추정에 대한 보정항을 뺀 `scoremod`의 분산을 사용하고,
군집을 지정하면 `sandwich::vcovCL`을 적용한다.
현재 Python은 두 정규화 평균의 비율 선형화 영향함수를 산업별로 합산한 뒤 multiplier 추론을 한다.
현재 식은 **가중치와 nuisance를 고정했을 때 두 비율 평균의 미분**으로는 맞다.

정규화한 가중치를 $\alpha_i,\beta_i$, 두 잔차평균을 $\bar r_a,\bar r_b$라고 쓰면
Python의 관측치별 기여는

$$c_i=\alpha_i(r_i-\bar r_a)-\beta_i(r_i-\bar r_b)$$

이다. 같은 제외 표본에서 R의 중심화한 점수를 표본 수로 나눈 값은

$$c_i^{R}=c_i+\bar r_b(\alpha_i-\beta_i)$$

이다. 비교군 잔차평균이 작아지는 조건에서 가까워질 수 있지만 유한 표본에서 항상 같지는 않다.
군집 소표본 보정과 유한 Bootstrap 추출도 추가 차이를 만든다.
따라서 표준오차가 다르다는 사실만으로 어느 쪽이 틀렸다고 할 수 없으며,
현재 방식에 저자의 분산 정리를 그대로 붙여서는 안 된다.

# 5. 2024 R 소스의 실제 구현 문제

1.1.1의 외부 Fold 학습 인덱스는 `trsample=idx[-tesample]`이다.
검증 관측치 번호를 섞인 벡터의 **위치**로 해석해 제거하므로 학습·검증이 겹칠 수 있다.
실제 R에서 12개 관측치·3 Fold·seed 1로 재현했을 때 교집합 수가 각각 **2, 2, 1개**였다.

또한 원래 순서 복원은 `param[sort(idx),]`인데, 순열을 정렬한 값은 `1:n`이므로
쌓아 둔 예측의 행 순서를 사실상 복원하지 않는다. 최신 1.1.6은 `order(idx)`를 사용한다.
최신 학습 인덱스도 실제 검증 관측치를 집합 차로 제거하는 방식으로 바뀌었다.

이것은 논문의 식별 논리가 틀렸다는 뜻이 아니라 **해당 역사적 구현의 문제**이다.
2024 소스를 그대로 복제하는 것이 적절한 검증 기준이 될 수 없는 이유이기도 하다.

# 6. 151개 산업에서 GPS 후보 평가

유의성이나 원하는 효과 부호를 사용하지 않고, 미리 정한 8개 GPS 후보를 비교했다.
각 후보는 4 Fold × 3회 반복의 산업 OOF 예측을 사용한다.
비교한 RF는 200개 나무이며, 사용 예제는 같은 깊이·잎 제한에서 300개 나무를 사용한다.
2023·2025년을 확인했지만 **GPS 입력이 같아 같은 캐시와 예측이 재사용되었다.**
따라서 서로 독립인 두 번의 검증이 아니라 동일한 151개 산업 자료에서의 한 비교이다.
아래 표는 2023년 값이며, 정규 NLL은 작을수록 좋다.

| GPS 후보 | 평균 예측 MSE | 정규 NLL | 처치 예측 95% 구간 포괄률 |
|---|---:|---:|---:|
| 기존 spline 5, 참고용 | 0.3819 | 6.9407 | 75.50% |
| Nested linear | 0.4078 | 1.1329 | 89.40% |
| Nested spline 3 | **0.3331** | 1.5835 | 86.09% |
| Nested spline 5 | 0.3819 | 1.9285 | 82.78% |
| RF 깊이 2, 최소 잎 10 | 0.4399 | 0.9238 | 93.38% |
| RF 깊이 3, 최소 잎 8 | 0.4161 | **0.8061** | 92.05% |
| RF 깊이 3, 최소 잎 15 | 0.4740 | 0.8971 | 93.38% |
| RF 깊이 4, 최소 잎 10 | 0.4358 | 0.8352 | 92.72% |

기존 모형은 nested 방식이 아니므로 참고값으로만 제시한다.
기존 모형에서 관측 처치의 예측밀도가 하한보다 작은 산업은 12/151개,
깊이 3·최소 잎 8 RF에서는 1/151개였다.

**RF를 사용할 수 없을 만큼 작은 표본은 아니며, 제한된 복잡도의 후보로 유지할 근거가 있다.**
그러나 평균 예측 MSE는 spline 3이 더 좋으므로 RF가 모든 면에서 우월하다고 말할 수 없다.
다음 탐색에서는 nested linear·spline 3·보수적 RF를 함께 두는 것이 합리적이다.
나무 수를 늘려도 독립 산업 수가 늘어나는 것은 아니다.

이 포괄률은 처치의 예측구간 진단이며 ATET 신뢰구간의 포괄률이 아니다.
같은 자료에서 후보를 고른 성능은 완전히 독립적인 최종 평가가 아니며,
이 비교만으로 정규분포 가정·식별 가정·DML 수렴률이 입증되는 것도 아니다.

# 7. 추가된 코드와 사용법

기존 1772 재현 기본값은 유지했다. 새 옵션을 선택해야 추정 방식을 바꾼다.

```bash
# 효과 추정 없이 GPS만 진단
python benchmark_gps.py --years 2023 2025 --repeats 3

# 향후 실행에 사용할 RF 설정
python run.py --config examples/gps_random_forest.json

# 기존 설정에서 GPS만 교체
python run.py --config examples/fixed_1772.json \
  --set 'gps_model="random_forest"' --set 'gps_fit_scope="nested"' \
  --set 'gps_params={"n_estimators":300,"max_depth":3,"min_samples_leaf":8,"max_features":0.75}'

# 커널·트리밍 등의 민감도 설정
python run.py --config examples/author_sensitivity.json
```

마지막 예제는 **R 전체 재현 모드가 아니다.** 산업 단위 표본 수·GPS 공변량·분산모형·밀도 하한 등의
차이가 남아 있는 상태에서 커널과 트리밍 등의 선택만 바꾸는 민감도 설정이다.
이 문서의 `run.py` 명령은 다음 작업을 위한 사용 예시이며 이번에 효과 패턴 탐색을 실행한 것은 아니다.

| `labor_did/gps.py` | 학습 표본 안에서 완결되는 평균·분산 모형, 보수적 RF |
